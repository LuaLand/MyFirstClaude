벽돌깨기

공통난읻
- 제한 시간 60.0초
- 블럭 총 개수는 24개, 난이도 마다 배치 다름. (단, 패들과 최하단 블럭 사이에는 충분한 공간이 확보됨)
- 블럭 1개 당 +10점
- (클리어 시) 남은 시간(초) * 10점
- (클리어 또는 타임 오버) 남은 라이프 * 100점
- 블럭 4개 파괴마다 스피드 업(공 및 패들 전부, 최대 5중첩)
Easy
공 속도: 1.0+0.2n(Max 2.0) , 쉬운 블럭 배치, 경험치는 득점의 1배
Normal
공 속도: 1.5+0.2n(Max 2.5), 평범한 블럭 배치, 경험치는 득점의 3배
Hard
공 속도: 2.0+0.1n(Max 2.5), 난해한 블럭 배치, 경험치는 득점의 5배
- Hard의 줄 수는 8에서 6으로. 이유는 정상 진행이 힘들어서


1. 개발의 구조
- Client(FrontEnd) : 유저들이 사용하는 화면과 기능 따위
- Server(BackEnd) : 데이터를 관리하고 전송하는 기능 따위
- 둘 다 다루는 행위 = FullStack
- FrontEnd 과거 : 퍼블리셔(디자인을 코드로 옮김)
- DevOps : 프론트와 백을 연결해주던 중간 다리 역할
- BackEnd : 자체 백엔드 서버를 구축(현재는 클라우드에 밀림)

- FrontEnd 개발자로써 필요한 개념
> Local State Management : 로컬 상태 관리
 * 지역 변수(페이지 하나)와 전역 변수(페이지 전체를 바꾸는 다크모드)/상수
> BackEnd Query : 서버 데이터 요청 기능
- BackEnd 개발자로써 필요한 개념
> Authentication : 인증관리(로그인아웃/가입탈퇴)
> Database (SQL/NoSQL)
* SQL : 구조화된 요청 언어(ex: 엑셀 시트)
* NoSQL : 비구조화(컬렉션 & 문서 단위 관리)
* DB 4대 작업 유형 : Create(생성), Read(읽기), Update(수정), Delete(삭제)
* 4대 작업 권한(rules) : 
1. Storage : text만 저장 가능한 DB의 단점을 보완하기 위해, 이미지, 영상, 한글, pdf 등의 파일을 저장하고, DB은 Storage의 'Link'를 참조함.
- Cached : 캐싱. 많이 쓰이는 파일을 내 기기에 임시저장하는 방법
2. Cloud Functions : 커스텀 백엔드 함수 생성
3. Messaging : (UID를 활용하여) 로컬 푸시 알림
